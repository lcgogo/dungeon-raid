# 测试报告标准 · Test Report Standard

本标准适用于 `test/reports/TEST_REPORT-*.md`。报告必须让读者能区分“活得久”“最后被谁击杀”和“哪个 Boss 造成长期压力”，三者不能互相替代。

## 1. 基本信息

每份报告必须记录：

- 引擎版本、报告日期、测试文件（正式版或开发版）
- 完整命令、每个配置的局数、敌人数值是否覆写
- 随机种子策略或确定性说明
- 回归套件及逐项结果

同一张主表的数据必须来自同一条命令、同一组输入。不同命令的结果必须分开成专项，不得混表。

## 2. 主表指标

默认职业线主表至少包含：

- 存活回合中位数、均值、最高值
- 等级中位数
- 达到一阶、二阶的比例
- `final_death_source`：死亡当回合伤害最高来源

`final_death_source` 必须标注为“最终致死来源”，不得简称为“威胁排名”或“总死因”。当前引擎的 `dmgBy` 只记录死亡当回合，因此它不能衡量跨回合累计压力、阻塞棋盘、分裂、加速或资源破坏。

## 3. Boss 威胁标准

不得只凭主表的最终致死来源判断 Boss 强弱。要声称某 Boss 是“最危险”或“最强”，至少提供以下一种专项数据：

- `--boss=<id> --games=N` 的单 Boss 隔离测试，并列出各族存活回合、达阶比例、最终致死来源；或
- 记录 Boss 出现后的存活回合变化、死亡率、Boss 造成的累计伤害/效果次数。

隔离测试只能说明该 Boss 在固定池中的压力，不能直接等同于完整 Boss 池中的排名。报告必须同时写明测试条件。

对于套娃、鞭笞者、小丑、岩浆魔等主要通过棋盘或全局效果施压的 Boss，必须在解读中注明：最终伤害统计会低估它们的间接贡献。

## 4. 解读规则

- “最稳”优先依据存活回合中位数，并注明样本量。
- “最能冲高”依据最高回合，但必须提示它对极端样本敏感。
- “最终致死来源最多”只能描述死亡当回合，不得改写成“全局伤害最多”。
- 主表与专项结论冲突时，保留冲突并解释条件，不强行选一个结论。
- 所有百分比注明分母；无死亡样本写 `—`，不能写成 0% 的威胁。

## 5. 最低报告结构

1. 基本信息与输入
2. 默认职业线主表
3. 生存/职业线解读
4. Boss 专项或威胁分析
5. 回归测试结果
6. 统计口径与限制
